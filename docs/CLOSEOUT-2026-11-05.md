## Claims, scope and unknowns

The concrete proposition is bounded: fixed synthetic events produce subject-correct
receipt fields and suppressed payloads; a fresh interpreter reads those committed
payloads/counters; actual HTTP routing requires explicit token authority; no network
publication is attempted. Identities are the frozen source, fixture, test environment
and hashed lane results. The owner/steward decides independent acceptance. Practical
SQLite/process/ASGI tests suffice for this small example; there is no formal proof
of production governance, complete history, committed-prefix ingestion or rollback.

Remaining limitations are not autonomous follow-up work:

- Receive queue is bounded, but cursor/acknowledgment, rollback loss, failed-root
  dequeue and shutdown drain semantics do not prove lossless intake. No live run.
- Heartbeat and process counters persist in SQLite, but consumer startup can reset
  counters. They are not durable lifetime loss totals. Missing health/store means
  unknown history; the legacy health endpoint may still return `ok`.
- SQLite WAL is enabled, but busy/maintenance scheduling and multiple writers have
  no sustained-operation acceptance. Label/receipt/audit/quarantine remain separate
  writes, with possible partial outputs and swallowed failures in legacy wrappers.
- Quarantine release is absent. Report promotion is local file generation under
  filesystem authority, not signed authorization or label release.
- Research rules may compare later posts, misclassify claims or repeat labels.
  Configuration hashes/fingerprint v1 identify behavior, not semantic correctness
  or migration safety. Invalid budgets can be silently ignored.
- The old distributed limiter does not compile; full-suite and historical
  dependency claims remain unqualified. No optional path is silently counted green.
- Public diagnostics disclose runtime details. The quickstart uses no service,
  production database, real DID or public exposure. Old Compose and worker paths
